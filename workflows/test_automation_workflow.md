
# Web3 测试自动化工作流

## 工作流概述

本工作流旨在将AI辅助工具与现有测试框架（ape）无缝集成，实现从接口文档输入到用例生成、执行、异常分析的全流程自动化。

## 工作流详细步骤

### 步骤1：接口文档输入

**输入内容**：
- 合约ABI文件（JSON格式）
- 接口文档（Markdown/PDF）
- 业务规则说明
- 已有的测试参考文档

**输入方式**：
- 在AnythingLLM中直接粘贴文本
- 上传文件到知识库
- 通过API接口传入

### 步骤2：用例生成（Skill 1）

**执行逻辑**：
1. AI读取输入的接口文档
2. 参考知识库中同类测试用例格式
3. 生成正向、反向、边界测试用例
4. 输出标准化用例文档和pytest代码框架

**输出内容**：
- 测试用例文档（Markdown格式）
- pytest测试代码框架（Python格式）
- 测试数据配置（YAML格式）

**Skill引用**：`case_generation_skill.txt`

### 步骤3：用例执行（ape框架）

**执行逻辑**：
1. 将AI生成的测试代码复制到ape项目的tests目录
2. 根据需要调整fixture和测试数据
3. 运行pytest执行测试
4. 收集测试结果和日志

**执行命令**：
```bash
cd /path/to/ape-demo
ape test --network ethereum:local:foundry
```

**输出内容**：
- 测试执行结果报告
- 通过/失败统计
- 异常日志（如有）

### 步骤4：异常分析（Skill 2）

**触发条件**：
- 测试执行失败
- 出现revert异常
- Gas消耗异常
- 资金对账不一致

**执行逻辑**：
1. 收集测试异常日志
2. 将日志输入到日志分析Skill
3. AI匹配故障案例库，分析根因
4. 输出问题分析报告和修复建议

**输出内容**：
- 问题分析报告（Markdown格式）
- 根因分析
- 代码修复方案
- 验证方法

**Skill引用**：`log_analysis_skill.txt`

### 步骤5：修复验证

**执行逻辑**：
1. 根据AI的修复建议修改测试代码或测试数据
2. 重新运行测试用例
3. 验证修复是否有效
4. 记录修复结果到知识库

## 典型使用场景

### 场景1：新接口测试用例生成

**流程**：
1. 收到新合约接口文档
2. 在AnythingLLM中输入接口文档
3. 调用用例生成Skill
4. AI生成标准化测试用例
5. 将用例复制到ape项目执行

**预期效果**：
- 用例覆盖率：≥90%
- 生成时间：<5分钟（原手动编写需1-2小时）
- 用例质量：符合团队标准格式

### 场景2：测试异常排查

**流程**：
1. 测试执行失败，产生异常日志
2. 将日志复制到AnythingLLM
3. 调用日志分析Skill
4. AI分析根因并提供修复建议
5. 开发者根据建议修复代码

**预期效果**：
- 问题定位时间：<10分钟（原手动排查需30分钟-2小时）
- 修复方案准确率：≥85%
- 避免重复问题：通过故障案例库积累

### 场景3：全链路自动化测试

**流程**：
1. 输入接口文档
2. AI自动生成测试用例
3. 自动写入ape框架执行
4. 自动收集异常日志
5. AI自动分析并给出修复建议
6. 循环执行直到测试通过

**预期效果**：
- 端到端耗时：<30分钟
- 人工干预：仅需用例微调
- 测试覆盖率：完整覆盖

## 工作流优化建议

### 短期优化
1. 完善知识库，增加更多测试场景
2. 优化Skill提示词，提高生成质量
3. 建立用例评审机制

### 中期优化
1. 增加测试数据生成Skill
2. 增加测试报告生成Skill
3. 实现与CI/CD流水线集成

### 长期优化
1. 增加合约安全审计Skill
2. 实现自动化测试代码生成
3. 建立测试知识图谱

## 注意事项

1. **数据安全**：确保知识库中的敏感数据已脱敏
2. **用例审查**：AI生成的用例需要人工审查后再执行
3. **故障积累**：每次分析的故障案例应及时补充到知识库
4. **技能迭代**：根据实际使用反馈，持续优化Skill提示词
